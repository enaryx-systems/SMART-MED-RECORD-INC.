# Security policy

Do not report security vulnerabilities in public issues. Contact the repository owner privately and
include reproduction steps, impact, affected versions, and a proposed mitigation when available.

Never commit credentials, private keys, access tokens, production database data, protected health
information, or patient documents. Rotate any exposed credential immediately and treat the exposure
as a P1 incident.

Critical dependency or code findings are P1. High-severity findings and unsafe transaction patterns
are P2. Both block merging. Moderate and low findings are P3 and remain visible without blocking.
